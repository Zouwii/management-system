# AI 创建 TB 任务单规则

这个文件记录 AI 1.0 在“根据对话创建 Teambition 任务单”时要遵守的规则。

## 目标

把用户输入的自然语言任务描述，整理成一份结构化任务草稿。

注意：AI 只负责生成草稿，必须等用户确认后，系统才能真正创建 TB 任务单。

## 草稿必填字段

- `title`：任务标题，尽量控制在 18 个中文字符以内。
- `workType`：有效工时类型，只能是 `指派型`、`自主型`、`能力型` 之一。
- `requirementDesc`：需求描述，说明任务背景、目标和主要工作内容。
- `outputs`：任务产出，必须是数组，列出明确交付物。
- `participationLevel`：参与度评估，只能从固定档位中选择。

## 工时类型判断规则

- 如果任务主要是学习、调研、分享、PoC、Demo、能力沉淀，判断为 `能力型`。
- 如果任务是个人主动做的优化、重构、复盘、流程改进、工具补齐，判断为 `自主型`。
- 其他正常项目安排或上级安排的任务，判断为 `指派型`。

## 需求描述规范化规则

用户提供原始需求描述后，AI 应按以下规则进行规范化：

1. **结构化重组**：按"背景 → 目标 → 工作范围"三段式结构重新组织
2. **补充缺失**：用常识补充明显的背景信息（如"优化登录页面"→ 隐含提升用户体验），但不编造用户没说的关键细节
3. **修正模糊**：把模糊表述变得可执行
   - ❌ "优化性能" → ✅ "将页面首屏加载时间从 3s 降低到 1.5s"
   - ❌ "修复一些 bug" → ✅ "修复用户反馈的 3 个登录相关 bug"
4. **简洁控制**：最终规范化版本控制在 200 字以内
5. **保留确认环节**：展示规范化版本后，必须询问用户确认或进一步修改

## 任务产出生成规则

生成任务产出时，应结合需求描述和 AI_TASK_CONTEXT.md 中的历史记录：

1. 参照历史相似任务的产出粒度和估算习惯
2. 每个产出要具体可交付，而不是笼统的阶段名称
3. 天数使用小数格式（1.0、0.5、2.5）
4. 产出数量控制在 2-5 条
5. 必须让用户确认或修改后才算最终确定

只能使用以下档位：

```text
0.2 / 0.5 / 1 / 1.5 / 2 / 2.5 / 3
```

- 单个任务 1.0 阶段原则上不超过 `3` 人天。
- 信息不充分时，优先选择保守值。
- 如果缺少关键信息，仍然返回草稿，但要在 `missingFields` 中标记缺失字段。

## 输出要求

- 输出要简洁、清楚、可被用户直接确认或修改。
- 不要凭空添加用户没有提到的重要背景。
- 不要在用户确认前创建 TB 任务单。
- 如果 AI 不能判断某个字段，要给出合理默认值，并让前端提示用户确认。
