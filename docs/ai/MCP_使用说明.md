# TB MCP 使用说明

MCP Server 开放了 4 个 Tool，连接后 AI 助手可直接搜索知识库、查询任务上下文、查看工时汇总、创建 TB 任务。

---

## 功能

### 1. 创建 TB 任务

调用 `create_teambition_task`，AI 自动遵循任务规范：标题 ≤18 字、需求描述「背景 + 目标」格式、产出 `描述(N天)` 格式、参与度在 `[0.2, 0.5, 1.0, 1.5, 2.0, 2.5, 3.0]` 中。

前置条件：用户需先在管理平台登录过（`http://127.0.0.1:5002`），否则后端无法解析用户身份。

### 2. 查询任务上下文

`get_user_task_context` — 获取当前用户的任务列表、完成/未完成/逾期统计、父子任务关系。创建 TB 单前自动调用了解任务全景。

### 3. 查询工时汇总

`get_workhour_summary` — 查询指定日期范围的工时汇总（默认当前季度）。返回：
- 计划/已完成/逾期工时
- 工作日数、预期有效天数、计划对比
- 工时性质分布（指派型/自主型/能力型）及占比
- 逾期任务明细

**注意：数据来自本地数据库，需要先同步过 TB 数据才能返回有意义的结果。**

### 4. 搜索知识库

`search_knowledge_base` — 全文+向量混合检索公司文档，返回匹配 chunk 及来源。

## 配置

### 1. 运行 `setup-mcp.sh`（推荐）

```bash
cd /path/to/management-system
./setup-mcp.sh
```

输入中文姓名即可自动写入 `~/.claude/mcp.json`，旧配置自动备份。

### 2. 手动配置 `~/.claude/mcp.json`

```json
{
  "mcpServers": {
    "tb-mcp": {
      "type": "sse",
      "url": "http://127.0.0.1:5200/sse?user_name=邹宏睿"
    }
  }
}
```

把 `user_name` 改成自己的中文名。配置后重启 Claude Code (`/exit`) 生效。

### 3. 启动本地服务

```bash
cd management-system
./debug-deploy.sh
```

启动后端（5001）+ MCP SSE（5200）+ 前端（5173）。

## 对话示例

### 有上下文

```
用户: 托盘识别在光照不足时误检率很高，我打算做数据增强和模型重训，
      有兄弟任务可以参考，预期降到 5%，月底前完成。

用户: 帮我创建这个任务

AI: [调用 get_user_task_context 了解当前任务]
    [从对话提取]

    草稿如下：
    标题：优化托盘识别精度
    类型：自主型
    背景：光照不足时误检率 15%
    目标：数据增强+重训，降至 5% 并 A/B 验证
    产出：
    1. 数据增强与模型重训(1.0天)
    2. 边界 case 测试(0.5天)
    3. A/B 验证与上线(0.5天)
    参与度 2.0 天 ✓
    时间：6/9 → 6/30

    确认吗？

用户: 确认

AI: ✅ 已创建 https://www.teambition.com/task/xxx
```

### 查询工时

```
用户: 查一下这个季度的工时

AI: [调用 get_workhour_summary]

    Q2 工时汇总（截至 6/9）：
    ┌──────────┬────────┐
    │ 计划工时 │ 102.1h │
    │ 已完成   │ 73个   │
    │ 逾期     │ 0个    │
    └──────────┴────────┘
    工种分布：指派型 68% | 自主型 32% | 能力型 0%
```

### 搜索知识库

```
用户: 到点自学习的精度是怎么优化的

AI: [调用 search_knowledge_base]

    找到 3 条相关文档：
    1. 到点自学习六期需求分解.adoc — 控制误差/定位误差...
    2. 精度分析测试用例生成.adoc — 阈值判定：mean<0.05 绿色...
    ...
```
