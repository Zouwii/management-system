## 1. 本阶段范围

当前 Markdown 下载链路已经具备，本阶段只设计和实现下载之后的两个阶段：

```text
下载得到 Markdown
    -> 清洗并写入 kb_documents
    -> 解析、切分并写入 kb_chunks
```

本记录用于持续维护已经确认的决策、样本观察、待确认问题、实现任务和验收结果。尚未通过样本验证的规则不得写成既定结论。

## 2. 已确认决策

### 2.1 `kb_documents` 的正文口径

- 下载得到的 Markdown 只是清洗输入，不要求作为正文长期保留。
- 清洗完成后的标准 Markdown 作为知识库的原文，写入 `kb_documents.content`。
- 后续结构解析和重新切分均以 `kb_documents.content` 为输入。
- `raw_json` 可以继续保存下载接口元数据，但不作为正文解析或检索来源。
- 接受该口径的直接后果：清洗规则变更后，如需恢复被删除的信息，应重新下载文档，而不是从数据库中的下载原稿恢复。

### 2.2 清洗与切分的边界

- 清洗阶段负责把混合 Markdown/HTML 转为语义等价、可稳定解析的标准 Markdown。
- 清洗阶段暂不负责按 token 生成检索块。
- 切分阶段从标准 Markdown 解析标题、段落、列表、表格、代码块、图片和业务实体，再生成 `kb_chunks`。
- `kb_chunks` 需要支持父子层级；具体字段和检索展开策略待样本分析后确定。

## 4. 样本带来的初步观察

以下是观察，不等同于最终清洗规则。

### 4.1 不能依赖单一 Markdown 形态

- 有标题的长文档可以形成标题树，但会议纪要可能完全没有 `#` 标题。
- HTML 列表既可能独立出现，也可能嵌在 Markdown 表格单元格中。
- 表格密集文档可能同时包含多张语义不同的表，不能把整篇文档识别成一张表。
- 图片可能承载关键流程图；即使 V1 不做图片理解，也需要保留图片与所在章节的关系和回链。
- 代码块必须作为不可穿透的结构单元，清洗普通文本时不能修改代码内容。

### 4.2 视觉格式可能携带状态语义

- `<span style="color: ...">` 有时只是视觉强调，有时表示新增、待确认或修订内容。
- `~~删除线~~` 在协议和版本表中通常表示废弃内容，直接去掉删除线符号会把废弃项变成当前有效知识。
- `<u>`、粗体和背景色大多可以降级，但在确定规则前需要统计其真实用法。

### 4.3 清洗和结构修复需要区分

可以较确定地做格式规范化，例如换行符统一、去除空样式标签；但下面这些属于结构修复，需要谨慎：

- 给相邻 span 补分隔符；
- 将 HTML 列表恢复成有层级的 Markdown 列表；
- 合并被空行拆开的同一张表；
- 识别中文序号形成的隐式章节；
- 判断删除线内容应该删除、降权还是显式标记为废弃。

## 5. Markdown 清洗规则 v1

清洗原则：保留全部可见业务内容和结构，只删除确定无意义的导出样式与容器噪声。需要理解业务内容才能决定的处理，留给结构解析和 chunk 阶段。

### 5.1 完整规则表

| 类别 | 输入或场景 | v1 处理 | 原因/边界 |
| --- | --- | --- | --- |
| 编码 | UTF-8 BOM | 删除 BOM | 非正文字符 |
| 换行 | CRLF、CR | 统一为 LF | 保证跨平台幂等 |
| 空格 | 不换行空格 | 转为普通空格 | 避免检索分词异常 |
| 行尾 | 行尾空格 | 删除 | 无语义 |
| 空行 | 多个连续空行 | 压缩为一个空行 | 缩短正文，保留块边界 |
| 代码 | 三反引号或三波浪线 fenced code | 整块保护，内部除换行外不清洗 | 防止命令、HTML 示例被误改 |
| 标题 | `# **标题**` | 转为 `# 标题` | 标题本身已有强调语义 |
| 标题 | 正常 `#` 至 `######` | 原样保留 | 后续结构树的主要依据 |
| 粗体 | 正文或表格中的 `**内容**` | 原样保留 | 可能表达重点，且不妨碍解析 |
| HTML 强调 | `<strong>/<b>/<em>/<i>` | 去标签，保留内容 | 消除混合 HTML；已有 Markdown 强调不受影响 |
| 删除线 | `~~内容~~` | 原样保留 | 明确表达废弃状态；chunk 阶段再决定是否召回 |
| span | `<span style="...">内容</span>` | 去标签和 style，保留内容 | 颜色含义不一致，不能推断业务状态 |
| 相邻 span | `</span><span ...>` | 去标签时补一个空格 | 避免 `上高压Bit2` 等文字粘连 |
| 相邻强调 | `**A****B**`（常由 HTML 去标签暴露） | 规范为 `**A** **B**` | 避免 Markdown 强调范围粘连，保持幂等 |
| 下划线 | `<u>内容</u>` | 去标签，保留内容 | 视觉样式降级 |
| font | `<font ...>内容</font>` | 去标签，保留内容 | 视觉样式降级 |
| 上下标 | `<sup>2</sup>`、`<sub>n</sub>` | 转为 `^2`、`_n` | 保留单位、公式含义并消除 HTML |
| HTML 代码容器 | `<pre><code>内容</code></pre>` | 去容器标签，保留内容和表格内 `<br>` | 样本中主要用于表格单元格 JSON 示例 |
| 容器 HTML | `div/p/section/article` | 正文转换为换行，表格单元格转换为 `<br>`，保留内容 | 容器本身不进入检索，但不能丢失块边界 |
| 未知 HTML | 非白名单标签 | 暂时保留并产生 warning | 防止误删可见内容 |
| 转义尖括号 | `\<index\>` | 原样保留且不视为 HTML | 常用于参数占位符和技术类型 |
| 普通正文换行 | 正文中的 `<br>` | 转为 Markdown 换行 | 恢复段落边界 |
| 表格换行 | 表格单元格中的 `<br>`、`<br/>` | 统一为 `<br>` | 直接换行会破坏 Markdown 表格 |
| HTML 列表 | 正文中的连续 `<li>` | 转为带缩进的 Markdown `-` 列表 | 保留列表和嵌套关系 |
| 表格内 HTML 列表 | 表格单元格中的 `<li>` | 转为 `•/◦`，项目之间使用 `<br>` | 保留层级且不破坏表格 |
| `:::` | 独占一行的 `:::` | 删除分隔符，保留其中正文 | 钉钉导出容器噪声 |
| 空标记 | 独占一行的 `[]`，或行首紧邻正文的 `[]` | 删除该空标记 | 不是合法的 `[ ]` 复选框且没有可见语义 |
| 空编号 | 独占一行且无正文的 `1.`、`一、` | 删除 | 空列表项噪声；有正文的编号保留 |
| 图片 | `![alt](URL "title")` | 优先提取 URL 路径 basename，转为 `【图片：basename】` | 删除长 URL，同时用真实文件名区分图片 |
| 图片回退 | URL 无法提取 basename | 回退到 alt；仍为空则转为 `【图片】` | 尽可能保留图片身份 |
| 普通链接 | `[文字](URL)` | 原样保留 | 链接是文档引用和证据回链 |
| 视频/附件链接 | `[文件名.mp4](URL)` 等 | v1 原样保留 | 当前只确认缩短图片，附件策略单独决定 |
| 转义符 | `\_`、`\+`、`\{` 等 | 原样保留 | 防止改变 Markdown 字面值和公式 |
| 表格 | Markdown 表头、separator、数据行 | 不合并、不改写为自然语言 | 表格结构修复属于 parser 阶段 |
| 图片理解 | OCR、图片摘要 | 不执行 | 属于后续多模态阶段 |
| 隐式标题 | `一、问题`、无标题会议纪要 | 不自动补 `#` | 属于结构解析，不是格式清洗 |
| 业务纠错 | 方向、单位、字段冲突 | 不修改，只允许 warning | cleaner 不推断业务事实 |

### 5.2 图片文件解析

服务器 Markdown 目录下的图片不是集中在一个全局 `images/`，而是分散在文档目录各级的 `images/` 子目录中。清洗正文只保留 URL basename：

```text
【图片：ffbe80c6-ae7c-4745-a476-b151b97364b8.png】
```

图片查找采用文档上下文定位：

```text
Markdown 文件所在目录 / images / 图片文件名
```

实现时可由文档 breadcrumb/source path 还原目录。不要只按文件名在全库随机取第一个结果，也不要在同级找不到时回退到任意同名图片。

2026-08-05 服务器核验结果：

- 共发现 1,069 个 `images` 目录；
- 共 19,921 个图片文件、18,551 个唯一文件名；
- 1,219 个文件名存在重复，最多重复 6 次；
- 其中 74 组同名文件大小不同，说明全局 basename 不能作为唯一键；
- 示例 `ffbe80c6-ae7c-4745-a476-b151b97364b8.png` 可在对应 Markdown 同级 `images` 中直接找到；
- 示例问题排查文档引用 13 张图片，其中同级目录实际存在 8 张，另外 5 张全库未找到，应按缺失图片处理。

因此不需要在 `kb_documents` 额外保存图片 URL 映射，但需要保留可还原文档目录的 source path/breadcrumb。

### 5.3 质量门禁

- 清洗结果不能为空；
- fenced code block 数量必须保持；
- 图片占位符数量必须与输入图片数量一致；
- 删除线内容和数量必须保持；
- 清洗结果再次清洗必须完全一致；
- 输出长度异常下降时拒绝覆盖上一次成功正文；
- 未知 HTML 标签、未闭合代码块等进入 warnings；
- 严重校验失败时不写入 `kb_documents.content`，后续重新下载再处理。

1. `<sup>/<sub>` 转为 `^/_`，例如 `m/s<sup>2</sup>` 转为 `m/s^2`；
