# 绩效填写顺序说明

> 更新: 2026-07-29

## 一、核心规则

绩效计算依赖 **上一季度的 `new_carry_balance`（结转余额）**。导入时系统自动读取上一季的结转值：

```
上一季 new_carry_balance  ──自动──▶  本季 prev_carry_balance  ──用于──▶  升档判断
```

**先填近期建立结转链，再往前补历史数据。**

## 四、对接组填写顺序

对接组完全空白，先建立近期结转链，再往前补。

### Step 1：2025 Q4

```
选 2026 /" → 不对，选 2025 / Q4 / 对接组
填 4 人（李赫、刘力璋、戴宇庆、谢宇迪）
→ prev_carry = 0（Q3 不存在）
→ 保存 → 自动计算 ✅
```

### Step 2：2026 Q1（触发结转）

```
选 2026 / Q1 / 对接组
填 4 人
→ prev_carry 自动读取 Q4 的 new_carry_balance ✅
→ 保存 → 自动计算 → 结转链建立完成 ✅
```

### Step 3：往前补历史

```
2025 Q3 → 填 4 人（prev_carry=0）→ 计算
2025 Q2 → 填 4 人（prev_carry=0）→ 计算
```

> 历史季度 prev_carry=0 不影响 Q4→Q1 结转链。补历史仅为数据完整性/趋势图展示。

## 五、导航组填写顺序

导航组 Q4 和 Q1 已有 6 人数据，需补 3 人 + 历史季度。

### Step 1：补 3 个缺失的人到已有季度

陈文斌、蒲曲、钟昌郎需要补录到 Q4 和 Q1：

```
选 2025 / Q4 / 导航组
→ 只填这 3 人的 work_hour_score + supervisor_score
→ prev_carry=0（新成员无历史）
→ 保存 → 自动计算

选 2026 / Q1 / 导航组
→ 只填这 3 人
→ prev_carry 自动读取 Q4 的 new_carry ✅
→ 保存 → 自动计算
```

### Step 2：填当前季度 2026 Q2

```
选 2026 / Q2 / 导航组
→ 填全部 9 人
→ prev_carry 自动读取 Q1 的 new_carry ✅
→ 保存 → 自动计算
```

### Step 3：往前补历史

```
2025 Q3 → 填 9 人（prev_carry=0）→ 计算
2025 Q2 → 填 9 人（prev_carry=0）→ 计算
```

## 六、汇总

| 步骤 | 导航组 | 对接组 |
|------|--------|--------|
| ① 建立结转链 | 补 3 人到 Q4 → Q1（已有 6 人不动） | Q4 → Q1（全新） |
| ② 当前季度 | Q2（填 9 人，结转来自 Q1） | Q2（填 4 人，结转来自 Q1） |
| ③ 补历史 | Q3 → Q2（prev_carry=0） | Q3 → Q2（prev_carry=0） |

**核心原则：先把 Q4→Q1→Q2 这条线串起来，结转自动正确。历史季度（Q3/Q2）补数据时 prev_carry=0，不影响已有结转链。**

## 七、常见问题

### Q: 组长（伍浩贤、沈旭东）需要填吗？
不需要。组长只记录，不参与自动计算。

### Q: 导入弹窗里看不到某个人？
character=9 的访客不会出现在导入列表。检查 `user_character` 表的 `team_id`。

### Q: 发现算错了怎么办？
在导入弹窗切到「手动编辑」Tab，直接修改各字段值。

### Q: 对接组和导航组可以分别填吗？
可以，完全独立，两张不同的数据库表。
