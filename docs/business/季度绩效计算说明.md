# 季度绩效计算说明

本文根据以下两份原始文件整理：

- `test.docx`：制度说明与文字口径
- `rules.xlsx`：实际落地表格与 Excel 公式

结论上，`rules.xlsx` 才是当前最直接的计算依据；`test.docx` 用于解释公式含义和版本演进。

## 1. 指标定义

### 1.1 工时绩效

`test.docx` 中的定义：

```text
有效工时分 = 1 + (完成有效工时 - 总有效工时) / 总有效工时
```

其中：

- 总工时 = 季度工作日天数 - 国家法定带薪假天数
- 组员总有效工时 = 总工时 * 0.7
- 组长总有效工时 = 总工时 * 0.4
- 出差有效工时 = 出差总工时 * 有效工时比例
- 完成有效工时来自 TB 任务单统计

### 1.2 主管评分

主管评分是人工评分项，评分档位在 `test.docx` 中定义为：

- `2.0` 杰出
- `1.5` 优秀
- `1.2` 超出期望
- `1.0` 符合期望
- `0.8` 需要提高
- `0.5` 需要改进
- `0.0` 不及格

## 2. 总体绩效

### 2.1 组员总体绩效

制度口径和 Excel 一致，公式为：

```text
总体绩效 = ROUND(工时绩效 * 0.7 + 主管绩效 * 0.3, 3)
```

`rules.xlsx` 中的直接公式示例：

```excel
=ROUND(AF5*0.7+AG5*0.3,3)
=ROUND(AK20*0.7+AL20*0.3,3)
```

未显式写 `ROUND` 的旧季度，缓存值同样按三位小数口径使用，例如：

```excel
=G20*0.7+H20*0.3
```

### 2.2 组长/主管总体绩效

这里存在版本切换。

#### 2025 Q1 及之后

`test.docx` 版本记录有“去掉组长 OKR 评分项”，Excel 也体现了新公式：

```text
总体绩效 = ROUND(小组平均绩效^2 * 0.6 + 主管评分 * 0.4, 3)
```

`rules.xlsx` 直接公式示例：

```excel
=ROUND(AF19^2*0.6+AG19*0.4,3)
=ROUND(AK19^2*0.6+AL19*0.4,3)
=ROUND(AP19^2*0.6+AQ19*0.4,3)
=ROUND(AU19^2*0.6+AV19*0.4,3)
```

#### 2024 Q2 到 2024 Q4 的旧口径

这一阶段 Excel 中组长公式仍包含 OKR 项，实际公式为：

```text
总体绩效 = ROUND(小组平均绩效^2 * 0.6 + 主管评分 * 0.2 + OKR归一化分 * 0.2, 3)
```

其中：

```text
OKR归一化分 = OKR / 0.83
```

`rules.xlsx` 直接公式示例：

```excel
=ROUND(Q19^2*0.6+R19*0.2+Q28/0.83*0.2,3)
=ROUND(V19^2*0.6+W19*0.2+V28/0.83*0.2,3)
=ROUND(AA19^2*0.6+AB19*0.2+AA28/0.83*0.2,3)
```

说明：

- `Q28`、`V28`、`AA28` 等单元格是该季度的 `OKR` 行
- 表头仍写作“工时绩效”，但从公式看，组长这里实际用的是“小组平均绩效/组长基准绩效”这一类团队指标

## 3. 结余绩效

Excel 的结余绩效定义非常直接：

```text
结余绩效 = 总体绩效 + 上季度剩余结余
```

`rules.xlsx` 直接公式示例：

```excel
=G4+C9
=K4+G9
=O4+K9
=S4+O9
```

首个季度没有上季度结余时：

```excel
=C4
```

也就是：

```text
首个季度结余绩效 = 总体绩效
```

## 4. 最终绩效

最终绩效不是连续值，而是按档位门槛离散化后的结果。

Excel 的实现逻辑是：

```text
如果 上季度结余 + 本季度补偿值 >= 0
  最终绩效 = 当前档位上限
否则
  最终绩效 = 当前档位下限
```

`rules.xlsx` 直接公式示例：

```excel
=IF(C9+G7>=0,I7,I8)
=IF(G9+K7>=0,M7,M8)
=IF(O19+S17>=0,U17,U18)
```

这里用到两个辅助量。

### 4.1 补偿值

补偿值表示“离下一档还差多少”，公式按区间分段：

```text
若绩效在 [0, 0.8)   ，补偿值 = 绩效 - 0.8
若绩效在 [0.8, 1)   ，补偿值 = 绩效 - 1.0
若绩效在 [1, 1.2)   ，补偿值 = 绩效 - 1.2
若绩效在 [1.2, 1.5) ，补偿值 = 绩效 - 1.5
若绩效在 [1.5, 2)   ，补偿值 = 绩效 - 2.0
```

Excel 原公式模式：

```excel
=IF(AND(C4>=0,C4<0.8),C4-0.8,
 IF(AND(C4>=0.8,C4<1),C4-1,
 IF(AND(C4>=1,C4<1.2),C4-1.2,
 IF(AND(C4>=1.2,C4<1.5),C4-1.5,
 IF(AND(C4>=1.5,C4<2),C4-2,"不在任何区间内")))))
```

补偿值通常为负数，越接近 0 说明越接近下一档。

### 4.2 区间上限

对应当前绩效所在档位的目标门槛：

```text
[0, 0.8)   -> 0.8
[0.8, 1)   -> 1.0
[1, 1.2)   -> 1.2
[1.2, 1.5) -> 1.5
[1.5, 2)   -> 2.0
```

### 4.3 溢出值

溢出值表示“超过当前档位下限多少”，用于生成新结余：

```text
若绩效在 [0, 0.8)   ，溢出值 = 0
若绩效在 [0.8, 1)   ，溢出值 = 绩效 - 0.8
若绩效在 [1, 1.2)   ，溢出值 = 绩效 - 1.0
若绩效在 [1.2, 1.5) ，溢出值 = 绩效 - 1.2
若绩效在 [1.5, 2)   ，溢出值 = 绩效 - 1.5
```

Excel 原公式模式：

```excel
=IF(AND(C4>=0,C4<0.8),0,
 IF(AND(C4>=0.8,C4<1),C4-0.8,
 IF(AND(C4>=1,C4<1.2),C4-1,
 IF(AND(C4>=1.2,C4<1.5),C4-1.2,
 IF(AND(C4>=1.5,C4<2),C4-1.5,"不在任何区间内")))))
```

### 4.4 区间下限

对应当前绩效所在档位的起点：

```text
[0, 0.8)   -> 0
[0.8, 1)   -> 0.8
[1, 1.2)   -> 1.0
[1.2, 1.5) -> 1.2
[1.5, 2)   -> 1.5
```

## 5. 本季度结余与衰减

### 5.1 首个季度

首个季度的新结余直接等于溢出值：

```text
本季度结余 = 结余绩效 - 当前档位下限
```

Excel 示例：

```excel
=C4-E8
```

对应衰减分数：

```text
衰减分数 = ROUND(本季度结余 * 0.25, 3)
```

Excel 示例：

```excel
=ROUND(C9*0.25,3)
```

### 5.2 后续季度

后续季度的结余逻辑是这份表最关键的部分。Excel 公式为：

```excel
=ROUND(
  IF(
    上季度结余 + 本季度补偿值 >= 0,
    IF(上季度结余 + 本季度补偿值 - 上季度衰减 >= 0,
       上季度结余 + 本季度补偿值 - 上季度衰减,
       0
    ),
    0.75 * 上季度结余 + 本季度溢出值
  ),
3)
```

实际单元格公式示例：

```excel
=ROUND((IF(C9+G7>=0,IF((C9+G7-E9)>=0,C9+G7-E9,0),0.75*C9+G8)),3)
=ROUND((IF(G9+K7>=0,IF((G9+K7-I9)>=0,G9+K7-I9,0),0.75*G9+K8)),3)
```

可以拆成两种情况理解：

#### 情况 A：结余足够把本季度推到更高档

```text
若 上季度结余 + 本季度补偿值 >= 0
  本季度结余 = max(上季度结余 + 本季度补偿值 - 上季度衰减, 0)
```

意思是：

- 先用上季度结余去补足到更高档
- 用完之后，再扣除 25% 的衰减
- 若扣完小于 0，则记 0

#### 情况 B：结余不足以升档

```text
若 上季度结余 + 本季度补偿值 < 0
  本季度结余 = 0.75 * 上季度结余 + 本季度溢出值
```

意思是：

- 上季度结余先按 25% 衰减，只保留 75%
- 再加上本季度新产生的溢出值

### 5.3 低绩效时结余归零

从 `rules.xlsx` 看，低档位会出现最终绩效为 `0` 的记录，并在表中显式出现“结余归0”的说明。结合 `test.docx` 的文字：

```text
绩效 0.8 以下处于需要改进档位，不进行结余
```

因此可整理为：

- 当最终绩效落入 `0.8` 以下档位时，不应继续累计正向结余
- Excel 中通过区间判断和 `max(...,0)` 已部分体现该约束

## 6. 对接组结余表 25年Q4 的实际计算公式

为了避免只看制度文字而忽略 Excel 的真实落地方式，这里单独按 `rules.xlsx -> 对接组结余表 -> 25年Q4季度绩效` 总结一次。

对应列关系：

- `AH/AI`：25年Q4 本季度结余
- `AJ/AK`：25年Q4 衰减分数
- `AD/AE`：25年Q3 相关结果
- `AA/AB/AC`：25年Q2 相关结余/衰减结果

这一列组的核心顺序是：

```text
1. 先算 Q4 总体绩效
2. 再算 Q4 结余绩效 = Q4 总体绩效 + Q3 本季度结余
3. 基于 Q4 总体绩效算补偿值 / 区间上限 / 溢出值 / 区间下限
4. 用 Q3 结余判断 Q4 是否能冲到更高档
5. 算出 Q4 的本季度结余
6. 再从 Q4 本季度结余里算 25% 衰减
```

### 6.1 25年Q4 总体绩效

对接组 Q4 的总体绩效单元格在 `AI` 列，示例：

- 沈旭东：`AI4 = 1`
- 刁怀锐：`AI14 = 1.077`
- 芦韩：`AI24 = 1.028`
- 李赫：`AI34 = 1.081`
- 陈凯伦：`AI44 = 1.06`

这些值是 Q4 的原始“总体绩效”，后续所有结余判断都围绕它展开。

### 6.2 25年Q4 结余绩效

Q4 结余绩效公式统一为：

```text
Q4结余绩效 = Q4总体绩效 + Q3本季度结余
```

Excel 直接公式：

```excel
AI5  = AI4  + AE9
AI15 = AI14 + AE19
AI25 = AI24 + AE29
AI35 = AI34 + AE39
AI45 = AI44 + AE49
```

对应结果：

- 沈旭东：`1 + 0.11 = 1.11`
- 刁怀锐：`1.077 + 0.035 = 1.112`
- 芦韩：`1.028 + 0 = 1.028`
- 李赫：`1.081 + 0 = 1.081`
- 陈凯伦：`1.06 + 0.002 = 1.062`

### 6.3 25年Q4 最终绩效

Q4 最终绩效统一公式：

```excel
=IF(Q3本季度结余 + Q4补偿值 >= 0, Q4区间上限, Q4区间下限)
```

Excel 直接公式：

```excel
AI6  = IF(AE9 +AI7 >=0, AK7 , AK8 )
AI16 = IF(AE19+AI17>=0, AK17, AK18)
AI26 = IF(AE29+AI27>=0, AK27, AK28)
AI36 = IF(AE39+AI37>=0, AK37, AK38)
AI46 = IF(AE49+AI47>=0, AK47, AK48)
```

含义是：

- `AE9 / AE19 / AE29 / AE39 / AE49` 是 Q3 留到 Q4 的结余余额
- `AI7 / AI17 / AI27 / AI37 / AI47` 是 Q4 补偿值，通常为负数
- `AK7 / AK17 / AK27 / AK37 / AK47` 是 Q4 区间上限
- `AK8 / AK18 / AK28 / AK38 / AK48` 是 Q4 区间下限

如果“上季结余 + 本季补偿值”大于等于 0，说明结余足够把本季推到更高档，最终绩效取区间上限；否则取区间下限。

对应结果：

- 沈旭东：`0.11 + (-0.2) < 0`，最终绩效 `1`
- 刁怀锐：`0.035 + (-0.123) < 0`，最终绩效 `1`
- 芦韩：`0 + (-0.172) < 0`，最终绩效 `1`
- 李赫：`0 + (-0.119) < 0`，最终绩效 `1`
- 陈凯伦：`0.002 + (-0.14) < 0`，最终绩效 `1`

可以看到，对接组 25Q4 这几个样本都没有发生“结余冲档成功到 1.2”的情况。

### 6.4 25年Q4 补偿值 / 区间上限

Q4 补偿值统一公式：

```text
补偿值 = 当前总体绩效 - 下一档门槛
```

但 Excel 是分段写法：

```excel
=IF(AND(AI4>=0,AI4<0.8),AI4-0.8,
 IF(AND(AI4>=0.8,AI4<1),AI4-1,
 IF(AND(AI4>=1,AI4<1.2),AI4-1.2,
 IF(AND(AI4>=1.2,AI4<1.5),AI4-1.5,
 IF(AND(AI4>=1.5,AI4<2),AI4-2,"不在任何区间内")))))
```

对应 Q4 的值：

- 沈旭东：`AI7 = -0.2`，`AK7 = 1.2`
- 刁怀锐：`AI17 = -0.123`，`AK17 = 1.2`
- 芦韩：`AI27 = -0.172`，`AK27 = 1.2`
- 李赫：`AI37 = -0.119`，`AK37 = 1.2`
- 陈凯伦：`AI47 = -0.14`，`AK47 = 1.2`

这些值说明这批 Q4 总体绩效都落在 `[1.0, 1.2)` 区间，距离 `1.2` 还差一小段。

### 6.5 25年Q4 溢出值 / 区间下限

Q4 溢出值统一公式：

```text
溢出值 = 当前总体绩效 - 当前档位下限
```

Excel 也是分段写法：

```excel
=IF(AND(AI4>=0,AI4<0.8),0,
 IF(AND(AI4>=0.8,AI4<1),AI4-0.8,
 IF(AND(AI4>=1,AI4<1.2),AI4-1,
 IF(AND(AI4>=1.2,AI4<1.5),AI4-1.2,
 IF(AND(AI4>=1.5,AI4<2),AI4-1.5,"不在任何区间内")))))
```

对应 Q4 的值：

- 沈旭东：`AI8 = 0`，`AK8 = 1`
- 刁怀锐：`AI18 = 0.077`，`AK18 = 1`
- 芦韩：`AI28 = 0.028`，`AK28 = 1`
- 李赫：`AI38 = 0.081`，`AK38 = 1`
- 陈凯伦：`AI48 = 0.06`，`AK48 = 1`

这里的 `AI8/18/28/38/48`，就是本季如果没能冲档时，可沉淀成新结余的“新增溢出”。

### 6.6 25年Q4 本季度结余

这是最关键的结余公式，Excel 直接写法如下：

```excel
AI9  = ROUND((IF(AE9 +AI7 >=0, IF((AE9 +AI7 -AG9 )>=0, AE9 +AI7 -AG9 , 0), 0.75*AE9  +AI8 )),3)
AI19 = ROUND((IF(AE19+AI17>=0, IF((AE19+AI17-AG19)>=0, AE19+AI17-AG19, 0), 0.75*AE19+AI18)),3)
AI29 = ROUND((IF(AE29+AI27>=0, IF((AE29+AI27-AG29)>=0, AE29+AI27-AG29, 0), 0.75*AE29+AI28)),3)
AI39 = ROUND((IF(AE39+AI37>=0, IF((AE39+AI37-AG39)>=0, AE39+AI37-AG39, 0), 0.75*AE39+AI38)),3)
AI49 = ROUND((IF(AE49+AI47>=0, IF((AE49+AI47-AG49)>=0, AE49+AI47-AG49, 0), 0.75*AE49+AI48)),3)
```

把它抽象成统一逻辑：

```text
若 Q3结余 + Q4补偿值 >= 0
  Q4本季度结余 = max(Q3结余 + Q4补偿值 - Q3衰减分数, 0)
否则
  Q4本季度结余 = 0.75 * Q3结余 + Q4溢出值
```

这就是这张 Excel 真正落地的“结余方式计算”。

注意点：

- 这里减掉的衰减分数，是上一期已经算出的衰减值，例如 `AG9 / AG19 / AG29 / AG39 / AG49`
- 如果无法冲档，不是简单“上期结余减衰减”，而是“保留 75% 上期结余，再加本期溢出值”

### 6.8 结余方式的最终总结

如果以后后台开发直接按 `对接组结余表 25年Q4` 来实现，最应该固化成代码的是下面这组规则：

```text
1. carryScore = overallScore + prevCarryBalance
2. compensationValue = overallScore - nextThreshold
3. overflowValue = overallScore - currentThreshold
4. finalScore =
   if prevCarryBalance + compensationValue >= 0
      then nextThreshold
      else currentThreshold
5. newCarryBalance =
   if prevCarryBalance + compensationValue >= 0
      then max(prevCarryBalance + compensationValue - prevDecayValue, 0)
      else round(prevCarryBalance * 0.75 + overflowValue, 3)
6. carryDecayValue = round(newCarryBalance * 0.25, 3)
```

这套规则比前面的制度文字更接近真实可开发口径，后续数据库建表和后台实现，建议以这组逻辑为主。

## 8. 一条完整计算链

按 Excel 的实际落地顺序，可以概括为：

### 普通组员

```text
1. 工时绩效 = 1 + (完成有效工时 - 总有效工时) / 总有效工时
2. 总体绩效 = ROUND(工时绩效 * 0.7 + 主管评分 * 0.3, 3)
3. 结余绩效 = 总体绩效 + 上季度剩余结余
4. 计算补偿值、区间上限、溢出值、区间下限
5. 最终绩效 = IF(上季度结余 + 补偿值 >= 0, 区间上限, 区间下限)
6. 新结余按“先用后衰减，否则衰减后累加溢出值”计算
```

### 组长/主管

2025 Q1 起：

```text
1. 总体绩效 = ROUND(小组平均绩效^2 * 0.6 + 主管评分 * 0.4, 3)
2. 后续结余绩效、最终绩效、结余衰减逻辑与组员相同
```

2024 Q2 到 2024 Q4：

```text
1. 总体绩效 = ROUND(小组平均绩效^2 * 0.6 + 主管评分 * 0.2 + OKR/0.83 * 0.2, 3)
2. 后续结余绩效、最终绩效、结余衰减逻辑与组员相同
```

## 9. 与制度文档的差异和注意点

整理后有 3 个需要特别注意的点：

1. `test.docx` 讲的是原则，但 `rules.xlsx` 才是最终计算实现。
2. 组长公式不是始终一致的，`rules.xlsx` 明确存在“含 OKR”到“去掉 OKR”的历史切换。
3. Excel 中很多季度的“总体绩效”缓存值已经算出，但公式字符串为空；这些单元格从相邻季度和结果值看，仍沿用相同计算口径。

## 11. 后台开发方案

建议按“先固化口径，再做计算引擎，再做发布流程”的顺序推进。

### 10.1 模块划分

建议后台拆成 5 个模块：

1. 基础资料模块
   负责用户、团队、角色、季度定义。
2. 规则配置模块
   负责绩效规则版本、分档门槛、结余策略配置。
3. 数据导入模块
   负责 TB 任务、考勤、主管评分、OKR 导入与校验。
4. 绩效计算模块
   负责单人/全员季度绩效试算、重算、发布。
5. 查询展示模块
   负责个人绩效历史、团队季度绩效、结余流水查询。

### 10.2 推荐开发顺序

#### 第一阶段：先做可落库的输入和结果表

先完成：

- `perf_user_quarter_input`
- `perf_rule_version`
- `perf_rule_threshold`
- `perf_quarter_result`
- `perf_carry_balance`

#### 第二阶段：实现纯后端计算引擎

核心建议：

- 计算逻辑不要写在 Controller
- 单独做 `QuarterPerformanceCalculator`
- 输入是统一 DTO，输出是完整 `calc_trace`

建议的服务拆分：

```text

QuarterPerformanceInputService
QuarterPerformanceCalculator
QuarterCarryService
QuarterPerformancePublishService
```

推荐的核心伪代码：

```text
1. 读取规则版本
2. 读取当前季度输入数据
3. 读取上季度 carry_balance
4. 计算 hour_score / team_avg_score / okr_score
5. 计算 overall_score
6. 依据规则区间计算 compensation_value / interval_upper / overflow_value / interval_lower

```

### 10.3 计算逻辑设计建议

#### 建议一：规则与公式解耦

不要把公式硬编码死在一堆 `if-else` 里。

建议：

- 组员公式用固定策略类
- 组长旧版公式用单独策略类
- 组长新版公式用单独策略类

例如：

```text
EmployeeQuarterFormulaStrategy
ManagerQuarterFormulaWithOkrStrategy
ManagerQuarterFormulaWithoutOkrStrategy
```

通过 `rule_version` 选择策略。

#### 建议二：所有中间值都要落库

至少把这些中间值落库：

- `overall_score`
- `carry_score`
- `compensation_value`
- `interval_upper`
- `overflow_value`
- `interval_lower`
- `prev_carry_balance`
- `carry_decay_value`
- `new_carry_balance`

否则后期排查会非常痛苦。

#### 建议三：公式计算统一保留三位小数

`test.docx` 已明确：

```text
每个环节的计算四舍五入保留三位小数
```

后端实现时建议：

- Java 用 `BigDecimal`
- 每一步统一 `scale=3, HALF_UP`
- 不要最后一步才 round

#### 建议四：支持重算但不能直接覆盖审计信息

建议：

- `perf_quarter_result` 保留最新版
- 历史重算日志单独记表，或在结果表加 `version_no`
- 发布后的结果不能随便覆盖，必须走“重算申请/重新发布”

### 10.7 风险点

后端开发时最容易踩的坑有 6 个：

1. 把制度文档公式直接写死，忽略 Excel 历史版本差异。
2. 把结余只存结果，不存流水，导致后面无法解释。
3. 只保留最终绩效，不保留中间字段，导致前端和 HR 无法核对。
4. 浮点数计算不用 `BigDecimal`，造成阈值比较漂移。
5. 不做规则版本，导致历史季度重算结果失真。
6. 发布后允许直接改结果，不留痕迹，后续无法审计。

## 13.2 通用工具函数

### 保留三位小数

```text
function scale3(value):
  if value is null:
    return 0
  return value.setScale(3, HALF_UP)
```

### 安全加减乘除

```text
function add(a, b):
  return scale3(a + b)

function sub(a, b):
  return scale3(a - b)

function mul(a, b):
  return scale3(a * b)

function div(a, b):
  if b == 0:
    throw BizException("division by zero")
  return (a / b).setScale(3, HALF_UP)
```

### 区间匹配

```text
function matchThreshold(score, thresholdList):
  for item in thresholdList ordered by lowerBound asc:
    if item.upperBound is null and score >= item.lowerBound:
      return item
    if score >= item.lowerBound and score < item.upperBound:
      return item
  throw BizException("score not in threshold")
```

### 求下一档

```text
function nextThreshold(current, thresholdList):
  find current index in thresholdList
  if current is last:
    return current
  return thresholdList[index + 1]
```

## 13.3 工时绩效计算

### 普通员工/主管个人项

```text
function calcHourScore(input):
  diff = input.completedEffectiveDays - input.targetEffectiveDays
  ratio = diff / input.targetEffectiveDays
  return scale3(1 + ratio)
```

对应制度口径：

```text
工时绩效 = 1 + (完成有效工时 - 总有效工时) / 总有效工时
```

## 13.4 总体绩效计算策略

建议按策略模式拆开。

### `EmployeeFormulaStrategy`

```text
function calcOverallScore(input):
  hourScore = calcHourScore(input)
  overallScore = scale3(hourScore * 0.7 + input.managerScore * 0.3)

  return {
    hourScore: hourScore,
    overallScore: overallScore
  }
```

## 13.5 区间辅助值计算

这一部分必须独立，不要散在主流程里。

```text
function calcThresholdAssistValues(overallScore, thresholdList):
  current = matchThreshold(overallScore, thresholdList)
  next = nextThreshold(current, thresholdList)

  currentLower = current.lowerBound
  nextUpper = next.lowerBound

  compensationValue = scale3(overallScore - nextUpper)
  overflowValue = scale3(overallScore - currentLower)

  return {
    currentThreshold: current,
    nextThreshold: next,
    compensationValue: compensationValue,
    intervalUpper: nextUpper,
    overflowValue: overflowValue,
    intervalLower: currentLower
  }
```

说明：

- 对 `[1.0, 1.2)` 档位，`intervalLower = 1.0`，`intervalUpper = 1.2`
- `compensationValue` 往往为负数
- `overflowValue` 是当前档位内已经超出的部分

## 13.6 结余绩效和最终绩效

### 结余绩效

```text
function calcCarryScore(overallScore, prevCarryBalance):
  return scale3(overallScore + prevCarryBalance)
```

### 最终绩效

```text
function calcFinalScore(prevCarryBalance, compensationValue, intervalUpper, intervalLower):
  if prevCarryBalance + compensationValue >= 0:
    return intervalUpper
  return intervalLower
```

### 最终绩效映射公司绩效

```text
function mapCompanyScore(finalScore, thresholdList):
  for item in thresholdList:
    if item.finalScore == finalScore:
      return item.companyScore
  return 0
```

## 13.7 结余计算核心函数

这是最重要的一段，建议原样固化。

```text
function calcNewCarryBalance(prevCarryBalance, prevDecayValue, compensationValue, overflowValue):
  canUpgrade = prevCarryBalance + compensationValue >= 0

  if canUpgrade:
    balanceAfterUpgrade = prevCarryBalance + compensationValue - prevDecayValue
    if balanceAfterUpgrade < 0:
      newCarryBalance = 0
    else:
      newCarryBalance = balanceAfterUpgrade

    calcMode = "upgrade_then_decay"
  else:
    newCarryBalance = scale3(prevCarryBalance * 0.75 + overflowValue)
    calcMode = "decay_then_add_overflow"

  return {
    newCarryBalance: scale3(newCarryBalance),
    calcMode: calcMode
  }
```

### 新衰减值

```text
function calcCarryDecayValue(newCarryBalance):
  return scale3(newCarryBalance * 0.25)
```

### 低绩效归零控制

如果业务最后确认“`0.8` 以下不允许继续结余”，建议单独加一道显式控制，而不是只依赖 Excel 隐式行为。

```text
function normalizeCarryByFinalScore(finalScore, newCarryBalance):
  if finalScore < 0.8:
    return 0
  return newCarryBalance
```

## 13.8 单人季度计算主流程

```text
function calculateOneQuarter(input, carryContext, thresholdList, ruleVersion):
  strategy = selectFormulaStrategy(ruleVersion.ruleCode, input.teamLead)

  formulaResult = strategy.calcOverallScore(input)
  overallScore = scale3(formulaResult.overallScore)

  assist = calcThresholdAssistValues(overallScore, thresholdList)

  carryScore = calcCarryScore(overallScore, carryContext.prevCarryBalance)

  finalScore = calcFinalScore(
    carryContext.prevCarryBalance,
    assist.compensationValue,
    assist.intervalUpper,
    assist.intervalLower
  )

  carryResult = calcNewCarryBalance(
    carryContext.prevCarryBalance,
    carryContext.prevDecayValue,
    assist.compensationValue,
    assist.overflowValue
  )

  normalizedCarry = normalizeCarryByFinalScore(finalScore, carryResult.newCarryBalance)
  carryDecayValue = calcCarryDecayValue(normalizedCarry)
  companyScore = mapCompanyScore(finalScore, thresholdList)

  return QuarterPerfResult(
    year = input.year,
    quarter = input.quarter,
    userId = input.userId,
    teamId = input.teamId,
    ruleVersionId = input.ruleVersionId,

    hourScore = formulaResult.hourScore,
    managerScore = input.managerScore,
    okrScore = input.okrScore,
    teamAvgScore = input.teamAvgScore,

    overallScore = overallScore,
    carryScore = carryScore,
    compensationValue = assist.compensationValue,
    intervalUpper = assist.intervalUpper,
    overflowValue = assist.overflowValue,
    intervalLower = assist.intervalLower,

    prevCarryBalance = carryContext.prevCarryBalance,
    prevDecayValue = carryContext.prevDecayValue,
    newCarryBalance = normalizedCarry,
    carryDecayValue = carryDecayValue,

    finalScore = finalScore,
    companyScore = companyScore,
    calcMode = carryResult.calcMode,
    ruleCode = ruleVersion.ruleCode,
    calcTrace = {
      "formulaResult": formulaResult,
      "assist": assist,
      "carryContext": carryContext,
      "carryResult": carryResult
    }
  )
```

## 13.9 批量季度计算流程

```text
function calculateQuarter(year, quarter):
  ruleVersion = ruleService.getEffectiveRule(year, quarter)
  thresholdList = ruleService.listThresholds(ruleVersion.id)
  inputList = inputService.listQuarterInputs(year, quarter)

  begin transaction

  for input in inputList:
    carryContext = carryService.getPrevQuarterCarry(input.userId, year, quarter)

    result = calculateOneQuarter(
      input,
      carryContext,
      thresholdList,
      ruleVersion
    )

    resultRepository.saveOrUpdate(result)

    ledgerRepository.insert({
      userId: input.userId,
      year: year,
      quarter: quarter,
      openingBalance: carryContext.prevCarryBalance,
      usedForUpgrade: max(-(result.compensationValue), 0) if result.calcMode == "upgrade_then_decay" else 0,
      newOverflowAdded: result.overflowValue if result.calcMode == "decay_then_add_overflow" else 0,
      decayValue: result.carryDecayValue,
      closingBalance: result.newCarryBalance,
      calcMode: result.calcMode
    })

    carryService.saveCurrentBalance(
      userId = input.userId,
      year = year,
      quarter = quarter,
      carryBalance = result.newCarryBalance,
      decayValue = result.carryDecayValue,
      resultId = result.id
    )

  commit transaction
```

## 13.11 重算流程伪代码

```text
function recalculateQuarter(year, quarter):
  lock quarter(year, quarter)

  archiveCurrentResults(year, quarter)
  clearCurrentCarryEffects(year, quarter)

  calculateQuarter(year, quarter)
```

实现建议：

- `archiveCurrentResults` 不要物理删除，最好做历史版本表
- `clearCurrentCarryEffects` 要从当前季度开始，向后检查是否已经发布后续季度
- 如果后续季度已发布，不能直接重算当前季度，必须触发“级联重算”

## 13.12 级联重算伪代码

因为结余跨季度传递，重算一个季度会影响后面所有季度。

```text
function cascadeRecalculate(startYear, startQuarter):
  quarterList = quarterService.listFrom(startYear, startQuarter)

  for item in quarterList ordered asc:
    archiveCurrentResults(item.year, item.quarter)
    clearCurrentCarryEffects(item.year, item.quarter)
    calculateQuarter(item.year, item.quarter)
```
